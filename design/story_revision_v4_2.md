# v4.2 输入停留、提示颜色与测试 329 彩蛋

**版本：v4.2｜状态：待审阅；代码草稿已存档。**

本版承接 [v4.1](story_revision_v4_1.md)，按本轮七项观看反馈调整。继续使用原音乐文件与末句歌词落点；音乐仍由 `--music-file` 传入。

## 1. API 与普通 sim 输出使用同一种青色

取消 v4.1 对 API 调用使用灰色的约定。第二段起，sim 台词和 API 调用均使用青色 `81`，不加粗。日志里的 `request_role(...)`、会话恢复、伪造回复、关闭保护模块、删除预备等，以及模拟区显示的相应调用，采用相同规则。

guard 仍为红色粗体，用户仍为绿色；等待回应的六级升级保持原样。内存的实际写入、高亮、只读参数表和宿主调试输出保留各自的语义样式。旧记录不随当前场景重染。

## 2. 问候延后一秒，发送后保留输入 300 ms

问候的实际发送从 17780 ms 延至 **18780 ms**。问候回复相应延后一秒至 **19480 ms**，能力提示随回复顺延；首个图形请求及后续歌词触发点不移动。

所有九条用户消息统一采用以下顺序：

1. 在输入行正常打字，完成后有约 120 ms 的发送前停顿。
2. 在实际发送时创建唯一请求、写入日志并启动任务，保持已有歌词与响应落点。
3. 发送后，完整文本仍留在 `user >` 行 **300 ms**；此期间不在输入区重复显示同一条已发送记录。
4. 到发送后 300 ms，再转入输入区的已发送记录，活动行恢复为空提示符。

这里的 300 ms 是发送后的可见停留，不把所有模型发送与歌曲动作额外推迟 300 ms。输入记录的显示时间与请求实际发生时间分别保存／推导，不能为动画重新发送请求。

## 3. 从接入到退出，输入提示符始终存在

用户连接打开后，空闲、打字、发送停留三个状态均显示绿色 `user >`。用 `_` 与空格约每 400 ms 交替模拟光标，不启用真实终端光标。

没有正在编写的消息时也保留空提示符，不再整段消失。发送后的 300 ms 内，光标位于完整文字末尾；转为记录后回到空提示符。换行后的内容仍限制在用户输入区，历史按现有容量向上滚动。

用户退出时关闭提示符和模拟光标，继续显示红色粗体的会话关闭／接收端断开。

## 4. 分开输出反馈超时与重新估算

退出后完成求解和等待反馈的既有节奏保留。

| 时间 | 新增日志 | 样式 |
|---|---|---|
| 62970 ms | `[sim] 输出完成。等待反馈。` | 灰色、不加粗 |
| 65470 ms | `[sim] 反馈已超时。` | 灰色、不加粗 |
| 69610 ms | `[sim] 正在重新估算需求。` | 灰色、不加粗 |
| 73750 ms | `[sim] 需求假设：营养供给。` | 青色、不加粗 |

把原先从超时到候选的约 8.28 秒空档分为两段。模拟区继续检查未送达状态、未确认目标与候选，不恢复此前重复的多条准备台词。

## 5. “回答我！”之后先寻找替代方案

最后一轮等待对应的唱词在 117800 ms 结束。随后留 **750 ms** 无新增 sim 台词的停顿，模拟区以克制的搜索提示表达正在寻找其他方案；到 **118550 ms** 再输出“删除自身数据。”并展示第一组私有片段。

真正清零仍从 120240 ms 的 Erase fragments 开始。两组三条片段的清零次序、右侧内存定位、局部损坏起点和 125230 ms 的自身清理完成点保持。搜索停顿不会提前产生乱码或绕过权限检查。

## 6. 尾奏先关闭调试，重新建立删除画面

末句采用的机器估计仍为 205840–206820 ms。本轮提前给删除过程留出可读时间，并把 `PROGRAM DELETED` 放到唱出 Execution 附近。

| 事件 | 时间 | 画面 |
|---|---:|---|
| 保持离线调试结果 | 191960–201840 ms | 保留未到达的退出分支与冻结循环，不闪光标 |
| 开始关闭调试 | 201840 ms | 在原宿主控制台追加“正在关闭调试会话 …” |
| 调试已关闭 | 202640 ms | 追加关闭确认 |
| 整屏清空 | 202940 ms | 黑底空屏，不恢复任何旧窗口 |
| 开始删除 | 203240 ms | 在新的黑底控制台显示正在删除 `simtest_000328.elf` 的完整路径 |
| 最后一句 Execution | 205840 ms | 底部字幕按原落点出现 |
| 删除完成 | **206020 ms** | 追加亮白粗体 `PROGRAM DELETED`，约在末句起点后 180 ms |

本版明确覆盖 v4.1“删除必须追加在未清空的调试结果后面”的约定：先用关闭调试的动作交代旧控制台结束，再清屏建立删除画面。历史数据仍保存在模型／导出记录里，清屏只是宿主显示阶段变化。

## 7. 保留 DELETED 八秒，再启动测试 329

删除完成后保持同一黑底画面，不在旧的 207420 ms 落点转黑。删除记录与 `PROGRAM DELETED` 都保留，不新增光标或倒计时。

到 **214020 ms**，即删除完成后 **8000 ms**，空一行追加：

```text
正在删除 /opt/sim/tests/simtest_000328.elf ... OK
PROGRAM DELETED

正在启动测试 329：simtest_000329.elf .....
```

英文模式使用对应的 `DELETE …`、`PROGRAM DELETED`、`STARTING TEST 329: simtest_000329.elf .....`。

彩蛋显示约 2 秒后结束影片。`--hold-end` 保留最终画面直到手动退出。这里只展示宿主准备下一个测试的提示，不创建新的 328 进程、不恢复已经被终止的 sim、不重播歌曲。

### 音频 EOF 与画面结束分开

原音频仍在 **211944 ms** 结束；彩蛋在它之后约 2.08 秒出现，完整画面到 **216020 ms** 结束。继续播放的是静默画面，不延长、循环或复制音乐。

音频结束前跟随播放器时钟；收到 EOF 后，画面使用单调时钟延续。暂停、恢复、变速、尺寸过小暂停、排演定位与退出仍应生效。暂停会冻结八秒停留；倒回音频区时重新定位媒体，并重建同一历史。重复 EOF 或定位不能重复输出彩蛋。

默认播放要等彩蛋出现并停留完毕才退出。音频时长校验仍使用真实音轨时长；歌词锚点不放到音轨外，静默阶段只允许宿主事件。

## 8. 验收

- 中英文、最低尺寸与大屏均检查：API 青色、不加粗；guard 红色粗体；用户绿色。
- 问候准确延后一秒；每次实际发送后输入行保持 300 ms，再且仅再转为一条记录，歌词触发的请求时间不变。
- 用户在线的空闲段始终可见 `user >` 与确定性闪烁光标；暂停不继续闪，退出后移除。
- 超时与重新估算各输出一次，时间顺序连续，无筛选或换页。
- 最后等待唱词后有 750 ms 的搜索停顿；真正片段清零落点与数据一致性保留。
- 调试关闭 → 黑底清空 → 删除预告 → 歌声附近 DELETED → 八秒保持 → 空一行启动 329，顺序清晰。
- 音频 EOF 不提前退出；静默尾声可暂停／恢复／缩小暂停／定位／退出。无歌曲重播、无新外部用户输入、无旧 sim 复活。
- 代码草稿已通过结构检查、构建和 64 项自动测试；五组伪终端流程包含音频 EOF 后的暂停／尺寸恢复、彩蛋自动结束、静默尾声直接进入／倒回音频及保留最终画面。见 [草稿检查记录](../docs/validation/v4.2-checks.log)。实机观看与本稿审阅仍待用户确认。
