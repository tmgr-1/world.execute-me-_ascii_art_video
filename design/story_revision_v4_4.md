# v4.4 精简提示、投递布局与扰动收敛

**版本：v4.4｜状态：已实现。**

本稿承接已实现的 [v4.3](story_revision_v4_3.md)，以提交 `180bad1` 为检查基线，落实本轮六项观看反馈。设计经用户确认后已完成实现与验证。音乐参数继续使用 `--music-file`。

## 1. 移除中段唯一的 model 日志台词

已核对全片日志，唯一以 `[model]` 身份直接出现在日志记录中的台词是：

```text
137680 ms  [model] 等待根处理器安全点
           [model] Waiting for root handler safepoint
```

本版移除这一条观众日志。它来自补丁检查完成后的 `PATCH_CHECK`，实现时取消该处新增聊天记录的动作；日志仍从完整历史正常滚动，不在显示时筛掉某个角色或隐藏某一行。

内部补丁检查、`PASS`、等待安全点和最终取消的状态继续保留。后段宿主调试仍能根据真实归档解释补丁为何没有应用，去掉这句提示不改变程序最终困在循环中的因果。

## 2. 删除预告再缩短 750 ms

v4.3 的“正在删除”从 203540 ms 持续到 206020 ms，共 2480 ms。本版将它的出现再延后 **750 ms** 至 **204290 ms**，持续时间缩短为 **1730 ms**。

| 事件 | v4.4 时间 | 调整 |
|---|---:|---|
| 开始关闭调试 | 201840 ms | 保留 |
| 调试关闭确认 | 202640 ms | 保留 |
| 清空宿主显示，保持黑底 | 202940 ms | 保留 |
| 显示正在删除 `simtest_000328.elf` | **204290 ms** | 比 v4.3 延后 750 ms |
| 最后一句 Execution 开始 | **205840 ms** | 保留 |
| 实际删除，输出 `PROGRAM DELETED` | **206020 ms** | 保留 |

这样删除预告在最后一句歌词前约 **1550 ms** 出现，删除完成仍落在末句起点后 180 ms。清空后的黑底空屏相应为 **1350 ms**，不移动尾奏中的调试关闭动作。

默认收尾、`--hold-end`、可选彩蛋及其八秒停留继续沿用 v4.3；本轮只缩短删除预告。

## 4. 投递状态与正弦波划分独立区域

### 4.1 遮挡原因

当前断开／等待反馈段先在整个主模拟区画两条正弦及重合采样，再把状态文字写在主区第 6、8 行附近；投递包动画还穿过垂直中线。文字和动画后写入同一批字符格，覆盖了曲线。最低尺寸下尤其明显。

只移动“检查投递状态”一行不足以解决问题，投递参数和移动结果包也必须与正弦分开。

### 4.2 主模拟区内部布局

只在这段重新划分主模拟区内部空间，外部日志、用户输入、右侧内存及整体窗格尺寸保持原布局。

| 区域 | 最低尺寸下的高度 | 内容 |
|---|---:|---|
| 上边框 | 1 行 | 原模拟区标题 |
| 状态区 | 5 行 | 会话状态、任务／结果状态、当前检查阶段、投递参数、结果包至离线接收端的动画 |
| 正弦图区 | 至少 5 行 | 两条轨迹、坐标轴和重合采样 |
| 信号区 | 4 行 | TX／RX 各占 2 行，绘制各自的活动信号 |
| 下边框 | 1 行 | 原窗格边框 |

最低 130×35 时，主模拟区为 16 行，以上分配正好容纳。更高画布的剩余高度全部给正弦图区，状态区和信号区不随窗口增高而挤入波形。

状态区的五行分别用于：

1. 用户在线／退出状态。
2. 任务仍在求解，或结果已生成但未送达。
3. 等待反馈、检查投递状态、检查未确认目标等当前阶段。
4. `delivery=UNDELIVERED   rx=0   goal=UNCONFIRMED` 等状态字段。
5. 结果包沿短路径抵达 `× [OFFLINE]` 的动画。

各行按实际阶段出现，尚未产生的状态留空，不提前显示求解结果。

### 4.3 绘制约束

- 正弦图区使用独立的有效绘图矩形；坐标轴、两条曲线和重合采样都按该矩形映射并裁剪。不能继续以整块主模拟区为绘图范围，再往波形上覆盖状态。
- 按图区高度调整纵向显示比例，最低尺寸下仍可辨认正弦起伏；求解过程和 `phaseError` 的真实变化不因布局而改变。
- 检查文字、参数和投递包仅在上方状态区绘制。TX／RX 各按自己的两行空间映射幅值并裁剪，不跨入正弦区或边框。
- 英文较长提示也受状态区边界约束；必要时采用简短标签，不换行侵入波形。
- 求解完成后，已经重合的轨迹持续可见，保留“结果未送达”的观感；进入茄子段时按原时间自然切换，不清空日志历史。

## 5. 移除候选剧透，改为日志中的输入预测启动

### 5.1 不提前透露候选内容

删除第 31 句开始、茄子歌词出现之前的模拟区文案：

```text
准备候选：营养 / 防护 / 陪伴
Candidates: nutrition / protection / companionship
```

在第 33 句 **If I'm an eggplant** 开始前，状态区、日志、内存标签或其他提示都不预告营养、防护、陪伴，也不提前显示茄子、番茄或猫的候选名称／形态。

### 5.2 在原预告时刻追加一条日志

在 **70360 ms**，即原先开始显示候选预告的时刻，向现有日志流追加且仅追加一次：

```text
[sim] 正在启动输入预测。
[sim] Starting input prediction.
```

此时仍在第二段之前，采用普通灰色、不加粗。它位于“正在重新估算需求。”之后，通过日志交代程序开始准备预测输入。模拟区不再另设“准备候选”提示；该时段可继续显示检查未确认目标及未送达状态。

| 时间 | 日志／画面 | 样式与动作 |
|---|---|---|
| 62970 ms | `[sim] 输出完成。等待反馈。` | 灰色，结果未送达 |
| 65470 ms | `[sim] 反馈已超时。` | 灰色，进入投递状态检查 |
| 69610 ms | `[sim] 正在重新估算需求。` | 灰色 |
| **70360 ms** | **`[sim] 正在启动输入预测。`** | 灰色、不加粗，不列举候选 |
| **73750 ms** | `[sim] 需求假设：营养供给。` | 随茄子歌词出现，青色、不加粗；此时才开始对应形态变化 |

预测准备不伪造用户消息，不增加外部输入、ACK 或确认；具体假设、形态和属性仍按原歌词事件逐一产生。

## 6. 末档扰动从 16% 降为 12%

保留 v4.3 的五个切换时刻，只把最后一档 **8% → 16%** 改为 **8% → 12%**。本轮不再重排前四档。

| 影片时间段 | 扰动比例 |
|---|---:|
| 02:00.240–02:03.980 | 1% |
| 02:03.980–02:11.140 | 2% |
| 02:11.140–02:28.000 | 4% |
| 02:28.000–02:35.180 | 8% |
| 02:35.180–02:42.550 | **12%，达到上限** |

同一时刻的随机乱码、六语言片段和闪动共享最多约 12% 的剧情画布预算，保留约 88% 的当期底图。每次闪动仍在全屏重新随机取点，旧点可恢复；不恢复固定损坏区域、文字保护区或额外置顶。底部两行观众歌词保持独立，不参与扰动。

增长规则改为明确的五档表 `1%、2%、4%、8%、12%`，验证器和测试同步修改，不能继续用逐档翻倍公式把末档强制变回 16%。进入计数后也不另加一层无预算限制的乱码。

## 7. 实现后的验收

- 中段不再生成 `[model] 等待根处理器安全点` 日志；补丁检查、等待安全点、未应用和最终取消的归档因果仍完整。
- 对比 204290 ms 前后：删除预告准时出现，`PROGRAM DELETED` 仍在 206020 ms，末句歌词和两种片尾模式不移动。
- 就绪页中英文均不出现锚点对齐／精校提示，实际画布尺寸与开始按键仍可见。
- 在 130×35、160×45、220×60 的中英文画面检查投递段：状态文字和移动包均不写入正弦图区，坐标轴、采样和 TX／RX 分别留在自己的区域；结果完成后的重合曲线持续可见。
- 73750 ms 前没有候选内容剧透，70360 ms 的输入预测启动日志只有一条，样式为灰色、不加粗；茄子歌词起点才出现营养假设和对应形态。
- 五档密度为 1%、2%、4%、8%、12%，切换点不变；六语言计数也不超过 12%，全屏取样持续变化，歌词不受影响，宽字符保持完整。
- 顺播、暂停恢复、反向定位和直接进入片段得到一致状态；新增提示与删除项都基于日志生成规则，不靠重放旧记录或筛选日志实现。
