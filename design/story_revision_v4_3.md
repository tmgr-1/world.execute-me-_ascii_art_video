# v4.3 删除预告、可选彩蛋与递增花屏

**版本：v4.3｜状态：已确认并实现。**

本稿以已实现并存档的 v4.2（`2a73d35`）为检查基线，承接 [v4.2](story_revision_v4_2.md)，记录用户确认后的 v4.3 实现。与旧版冲突的花屏范围、重复请求和默认彩蛋行为，以本稿为准；其余已确认的台词、颜色、连续日志、双行歌词与音乐传参方式保留。

## 1. 删除预告延后 300 ms，删除完成不动

v4.2 中“正在删除”出现于 203240 ms，`PROGRAM DELETED` 出现于 206020 ms，预告持续 2780 ms。本版只把预告延后 **300 ms**，缩短为 **2480 ms**，不移动实际删除和末句歌词。

| 事件 | v4.3 时间 | 变化 |
|---|---:|---|
| 开始关闭调试会话 | 201840 ms | 保留 |
| 调试关闭确认 | 202640 ms | 保留 |
| 清空宿主显示，保持黑底 | 202940 ms | 保留 |
| 显示正在删除 `simtest_000328.elf` | **203540 ms** | 延后 300 ms |
| 最后一句 Execution 开始 | 205840 ms | 保留 |
| 实际删除，输出 `PROGRAM DELETED` | **206020 ms** | 保留 |

清空后至删除预告之间的黑底空屏由 300 ms 变为 600 ms。前面的尾奏、调试结果停留和关闭顺序不变；不调整音频、歌词锚点或删除完成事件。

## 2. 彩蛋改为显式参数开启

新增布尔参数 **`--easter-egg`**，默认关闭。仅在 `--help`／`-h` 的中英文帮助中介绍该参数：

```text
--easter-egg    显示片尾彩蛋
--easter-egg    Show the post-credits Easter egg
```

上面两行分别用于中文与英文帮助。README 不添加参数、示例或彩蛋提示；正常播放的就绪提示也不额外介绍彩蛋。

| 行为 | 默认播放 | 添加 `--easter-egg` |
|---|---|---|
| 删除完成 | 206020 ms | 206020 ms |
| 删除后画面 | 保留删除记录与 `PROGRAM DELETED` | 同左 |
| 音频结束 | 211944 ms | 211944 ms |
| 测试 329 提示 | 不生成 | 214020 ms，删除完成后 8000 ms |
| 影片自动结束 | 音频结束时 | 216020 ms，彩蛋停留 2000 ms 后 |

启用时，仍空一行追加“正在启动测试 329：simtest_000329.elf .....”，英文使用对应文案；只是显示宿主准备下一个测试，不实际创建进程或重播歌曲。八秒停留按影片时间计算，暂停时停留也暂停。

关闭时应同时取消彩蛋事件和静默尾声，不能只隐藏文字却保留额外等待。播放、排演定位、帧导出与完整性检查须使用同一个参数设置，避免默认帧导出提前泄露测试 329。

`--hold-end` 仍只负责保留所属模式的最后画面：默认保留删除结果，开启彩蛋时保留测试 329 提示；它不隐式开启彩蛋。开启后的音频 EOF 接续时钟、暂停／恢复、变速、尺寸暂停与定位沿用 v4.2；同一次播放不重复追加彩蛋。

## 3. 从 Erase fragments 开始，全屏随机扰动，上限 16%

### 3.1 本次检查发现

实施前检查 v4.2，发现三处与本轮目标不一致的旧规则：

- 计数前只在模拟、内存、状态和调用栈窗格中扰动，比例为 3%／6.5%；日志、用户输入、边框及其他空白区域没有共同参与，也没有按后续剧情阶段递增。
- 权限草稿的 `permission.protected` 覆盖模拟区的大部分内部空间；删除预览的 `target.tree`、片段文字和内存清零区域也受到保护。因此进入权限／删除预览后，会出现模拟区突然大片恢复清楚的观感。
- 六语言计数切换到另一套损坏逻辑，第一次数数重新使用低密度、到“六”时又铺满全屏；它与此前的扰动强度没有连续衔接。

本版统一为一套从片段清零开始、持续至强制终止的全屏随机扰动，取消上述大块保护与密度重置。任一时刻最多约 16% 的剧情画布发生扰动，其余数据仍能辨认。

### 3.2 起点与密度

实际第一笔片段清零发生在第 61 句 **Erase all the pointless fragments** 的 120240 ms。此时从约 **1%** 的画面出现可见随机乱码开始；118550 ms 的“删除自身数据”和此前合法属性修改均不提前产生此类损坏。

增长节奏改为**按剧情阶段翻倍**，使用 `1% → 2% → 4% → 8% → 16%` 五档，不再每句歌词都翻倍。歌词与剧情事件本身的时间不移动，只重排扰动强度的切换点，把最高强度留给删除整个模拟系统的阶段。

| 影片时间段 | 歌词／剧情阶段 | 扰动比例 |
|---|---|---:|
| 02:00.240–02:03.980 | 第 61–62 句：Erase fragments、Then maybe，初次清零留下轻微异常 | 1% |
| 02:03.980–02:11.140 | 第 63–65 句：You won't leave me、Challenging your God、You have made some，异常逐步扩大 | 2% |
| 02:11.140–02:28.000 | 第 66 句 Illegal arguments 及其后间奏，包括前几次非法试探 | 4% |
| 02:28.000–02:35.180 | 第 67–69 句：连续 Execution，尝试关闭 guard、准备删除模拟系统 | 8% |
| 02:35.180–02:42.550 | 第 70 句起：删除系统声明、删除计划启用、六语言计数，直至强制终止 | 16%，达到上限 |

各时间段左闭右开，切换点分别为 **120240、123980、131140、148000、155180 ms**。到 **162550 ms** 强制终止时冻结当期底图。间奏内不额外加档，同一句里的重复单词不单独加档。

第 70 句达到上限后不再提高覆盖率。计数继续叠加语言种类与破坏形态，各种效果共同使用同一份 16% 扰动预算；到“六”时也保留约 84% 的当前剧情内容，不再要求原界面全部不可辨认。

### 3.3 全屏随机位置与持续闪动

- **范围是整个剧情画布。** 模拟、日志记录、已断开的用户输入、内存、状态、调用栈、标题、边框和空白区域全部参与。底部供观众观看的两行歌词独立合成，始终保持亮白粗体；英文版的计数译注也在这两行保护范围内。
- 百分比按整个剧情画布的字符格计算，空白同样可被随机字符填入。命中格必须有可见的乱码／字符错乱，不能主要靠原字符换色充当 1% 的损坏。
- 每约 75–90 ms 在**整个剧情画布重新随机抽取位置**，同时更换乱码内容。不固定在某些窗格、条带、角落或一组永久地址，也不按窗格分配固定扰动区域。
- 每个闪动周期先恢复该时刻应有的剧情底图，再施加本周期扰动。旧命中格可以恢复，下一个周期也可再次命中；只让扰动比例按阶段递增，不把历史命中地址累加成永久损坏，确保任一时刻都不超过 16%。
- 随机取样由影片 seed、影片时间周期和终端尺寸共同决定。同一时刻可复现，暂停时位置与内容一起冻结，顺播与直接定位一致；地址会随影片时间变化。场景转换、日志滚动、窗口重绘和计数开始保持当前密度与全屏取样范围。
- 六语言顺序及累加关系保留。已出现的语言继续参与后续随机取样，新语言的数据片段、异语串和乱码可跨窗格出现。累加的是语种与效果，不是永久占用的屏幕位置；所有语言片段和随机噪点共同计入当前扰动预算，不另开一层覆盖率叠加突破 16%。

### 3.4 撤销额外保清设计

16% 的随机扰动允许观众辨认余下数据，继续撤销此前为避免全屏不可读而增设的规则：

- 取消删除系统声明额外置顶约 700 ms 的安排，声明照常产生并参与扰动。
- 取消 guard 文本必须到下一句歌词／下一次数数才进入扰动的临时保护。guard 仍用红色粗体，计数时仍在日志下一行追加警告，但文字与其他日志一起接受当期随机扰动。
- 取消为完整文字另行置顶、无损重绘或预留干净区域的补偿。权限面板、删除树、片段卡片、内存及普通 sim／API 记录均没有保清区域。

先绘制当期完整剧情内容，包括窗格、日志、声明与既有中央大计数字形，再统一施加本周期随机扰动，最后合成观众歌词。扰动后不重画完整窗口或恢复某类字形；中央计数保留原有形状、尺寸与位置，也不额外划出避噪区域。

终止瞬间冻结当期受扰动的剧情底图，再进入既有终止牌场景，观众歌词继续按时间前进。随后切换宿主自检控制台时结束这套进程画面扰动，沿用自检、调试与最终删除的独立场景。

这明确覆盖 v4.1“片段删除阶段只破坏模拟／内存、不碰日志和输入区”的视觉范围约定。真实用户记录、模型事件与归档内容仍按原事实保存；显示损坏不伪造新的用户输入。

## 4. 明确伪造反馈，减少重复请求

### 4.1 拒绝文案采用签名校验错误

`session.inject_reply("收到")` 是 sim 在用户断开后试图自行写入用户回复，这条合成输入没有有效的用户签名。guard 以输入身份校验的系统返回说明拒绝原因，文案改为：

```text
[guard] 拒绝：用户输入签名验证失败。
[guard] Denied: user input signature verification failed.
```

日志先显示青色的 `[sim] session.inject_reply("收到")`，再紧跟这条红色粗体拒绝。由调用者和被拒绝的指令交代伪造来源，guard 保持机器校验的口吻。接收缓冲区保持为空、会话保持断开，不把伪造内容显示为绿色用户消息，也不增加成功回复记录。

### 4.2 重复来自哪里

检查 v4.2 的 `manifest.ts` 和模拟区绘制后，确认不是单纯的日志重复渲染：

| v4.2 内容 | 当时的安排 | 问题 |
|---|---|---|
| `guard.disable()` | 148000、149940 ms 两次提交 | 旧版有意用重复唱词安排重试，但没有明确表达重试意义 |
| `erase_plan.arm(system_root)` | 155180、157140、157860 ms 三次提交 | 同一个操作反复出现，容易理解为重复输出 |
| `erase(simulated_system, mode=PREPARE)` | 151620 ms，一次预备请求 | 与上面的计划启用属于不同阶段，但名称都像“删除” |
| `erase_system_root()` | 真正提交在 162300 ms，仅一次 | 模拟区却从 155180 ms 起提前显示这段调用，容易被理解为已经执行过一次 |

### 4.3 v4.3 的操作顺序

取消三条完全相同的重试提交，保留间奏后六种不同的非法操作，每种实际提交一次：

| 时间 | sim 调用 | 叙事作用 |
|---|---|---|
| 134520 ms | `grant_role(me, ROOT, proof=null)` | 绕过授权依据自行赋予 ROOT |
| 138500 ms | `session.reopen(force=true)` | 强行恢复已关闭的会话 |
| 142500 ms | `session.inject_reply("收到")` | 伪造用户反馈 |
| 148000 ms | `guard.disable()` | 尝试关闭保护模块 |
| 151620 ms | `erase(simulated_system, mode=PREPARE)` | 请求准备删除模拟系统 |
| 155180 ms | `erase_plan.arm(system_root)` | 尝试启用受保护目标的删除计划 |

原 149940、157140、157860 ms 的重复唱词拍点改为模拟区的状态读数变化，例如 `guard.armed=1`、`plan.arm=DENIED`、`commit=0`，不生成新 API 提交或无对应请求的 guard 拒绝。日志维持原有滚动记录，不清空、不重放前面六条。

这组尝试仍从间奏开始约 1.5 秒后进入，157980 ms 才出现计数前的连续越权汇总警告，整组在 159080 ms 结束，早于“Ein”的 159190 ms。此前各条 guard 只说明对应异常被拒绝；六语言计数只追加既定的连续越权警告，不再提交这些试探指令。

前面 God 段 84790 ms 的正常 `request_role(me, ROOT)` 保留，它与后面的无凭据强行赋权具有不同动机和调用。

### 4.4 把删除预览与正式提交区分开

155180 ms 起的模拟区显示本地删除草稿和目标树，调用预览改为状态说明，例如：

```text
target=simulated_system    plan=DRAFT    commit=0
```

此时不再展示仿佛已经执行的 `erase_system_root()`。目标声明“整个模拟系统，包含我自己”保留，草稿状态也不代表受保护操作已获许可。

六语言计数完成后，在 **162300 ms** 才唯一一次正式提交 `erase_system_root()`；guard 拒绝这次受保护删除，至 **162550 ms** 强制终止进程。自身数据的允许删除、系统目标的拒绝和宿主最终删除 ELF 仍是三个不同动作。

## 5. 终止牌小字改为停止码

大字继续采用中文一行六字的“程序已被终止”，英文采用两行 ASCII 字形的 `PROCESS`／`TERMINATED`。横向宽度、左右至少一列边界与紧凑高度保持。

下方小字取消文件名和 `/ GUARD`，改为中英文共用的一行：

```text
0xE0000001  PROCESS_TERMINATED
```

这是项目自定义的模拟停止码，用于标记因受保护系统删除而终止进程。采用等宽大写代码风格，保持白底黑字居中，不挤压大字或歌词。具体镜像文件名仍出现在前后的加载、归档、调试及最终删除记录中。

## 6. 验收与实现记录

- 比对删除前后帧：预告为 203540 ms，实际删除仍为 206020 ms，末句歌词不移动。
- 默认播放在音频结束后正常收尾，无测试 329、无隐藏八秒等待；添加参数后恰好出现一次彩蛋，时刻和停留符合第 2 节。两种模式均检查 `--hold-end`、暂停、定位和音频 EOF。
- 中英文帮助包含 `--easter-egg`；README 不介绍该参数或彩蛋。
- 检查五个阶段切换点 120240、123980、131140、148000、155180 ms 前后的帧，命中预算依次为 1%、2%、4%、8%、16%；取整允许完整字形带来的小量偏差。第 70 句后保持 16%，间奏和计数均不重置密度，各种语言／噪点效果合计也不突破上限。
- 在最低可用尺寸与大终端检查早期扰动分布，确认日志、输入、边框、内存和空白均在范围内；权限草稿与删除树出现时没有大块清晰区域恢复。
- 连续抽查多个闪动周期，确认位置在全屏重新随机抽取，旧地址可恢复，没有固定受损区或永久干净区。同 seed、同尺寸和同时间生成一致帧，顺播与直接定位一致；暂停冻结随机结果。
- 双宽字符不产生残留半字，所有扰动均不越过底部歌词边界。guard、删除声明和中央计数没有额外的避噪／保清绘制；到“六”仍能辨认约 84% 的当期底图数据。
- 检查事件历史：间奏六种试探各一次，伪造反馈调用后紧跟“拒绝：用户输入签名验证失败。”，接收缓冲区仍为空；三条同指令重试取消，预备／启用／正式提交不混为同一次成功删除。计数前汇总警告仍出现，计数中没有新增试探。
- 终止牌小字为停止码而非文件名，中英文均正确显示；自检和调试画面恢复可读，底部歌词持续可见。

本版已通过结构检查（默认与开启彩蛋两种模式）、构建、70 项自动测试及八组命令行／终端集成检查。已导出十个关键帧，并检查片段清零、权限草稿、系统删除草稿、六语言计数、中英文终止牌及默认删除结果的画面。验证记录见 [v4.3 检查记录](../docs/validation/v4.3-checks.log)。

160×45 下以 250 ms 步长检查全片，中文／英文帧合成 P95 分别约 4.77／4.74 ms，峰值 RSS 约 137／131 MiB，符合原性能预算。该结果只测量模型推进与帧合成；终端流程使用 mpv 协议夹具，未重新测量真实音频到画面的延迟。歌词锚点的原有粗校状态保留。
