伪终端使用 `xterm-256color` 与明确的 JSON 播放器协议替身，检查备用屏幕、原始输入恢复、暂停／定位、缩小暂停、恢复不自动续播、背压和播放器异常。它不播放音乐，不证明音频设备延迟。自动化沙箱禁止 mpv 的本地 socket 发送系统调用（EPERM）；真实播放依赖用户普通终端复测。

PNG 帧检查采用 DejaVu Sans Mono 16 px / Noto Sans CJK 18 px 及相应粗体字形，10×20 px 字符格。v4.0 的 46 张帧保存在本地 `.cache/v4-review/`；v4.1 重建了 156 张 JSON 帧，其中 90 张关键帧另存为 PNG，位于 `.cache/v41-review/`，覆盖 ASCII 条、完成保持、连续日志、两组私有片段、清零定位、只读追溯与参数检查、计数警告、终止标题和末句追加清理。这不是设计中 1920×1080、15 号字体桌面环境的实测。用户的终端软件、字体、缩放、音频设备、开头／中段／高潮／尾声的声画延迟尚未记录。Windows、macOS 未测试。

## 时间轴精校

音轨时长 211.944 秒。原参考歌词 92 行，设计为 93 行；差异为重复的 `You have left`。按设计保留 93 节点，原文件保持原样。`timing-evidence.json` 保存分段强制对齐证据，不代表已听音复核。

此前采用本地 small 权重，对 12 个短段重新对齐并以 20 ms 搜索步长细化边界，再与原分段对齐和独立转写比对。合并 32 处局部修正，其余未取得一致证据的位置保留原值。原始短段结果见 `films/world-execute/timing-refinement.json`；采用／推迟记录见 [时间轴比对](validation/timing-refinement.json)。该次对齐没有修改全局偏移、剧情程序或将状态批量改为已精校；v3.2 与 v4.0 的剧情改动在其后单独实施，沿用这些锚点。

较明显的修正为第 9 / 11 / 13 行原先被压为零时长的首词 If，分别提前 190 / 200 / 400 ms；第 85 行 I've studied 起点从 177580 调至 177360 ms。大部分其他修正在 10–40 ms 内。概率细化产生的过短词尾、重复 Execution 的大幅漂移及最后单词的裁切边缘命中均未直接采用。20 ms 搜索步长不代表 20 ms 实测精度。

当前估计：第 76 行结束 162300 ms；意图至 162550 ms；冻结至 165550 ms；补丁尾声从 177360 ms 开始。六个计数为 159190、159430、159880、160390、160790、161190 ms。第 76 行词尾的新候选为 162240 ms，因置信度不足而保留旧值。所有这些值均待听音复核。

可使用 `--rehearsal --loop 02:38..02:46` 反复试听计数和阻断，循环会精确定位媒体并重建模拟状态，不重复累积请求。仅在明确完成听音复核后，使用 `calibrate` 保存批准结果，并运行 `check --release`。

## v4.1 末句局部复核

原 192480–194480 ms 的窗口没有覆盖尾奏后的实际末词。使用本地 small 权重，对 188 秒至解码 EOF 的尾段与多个独立窗口比较；采用末词 205840–206820 ms，前 92 行与全局偏移保持原值。不同文字写法的候选起点相差约 200 ms，末尾集中在 206760–206820 ms；从 207 秒才开始的窗口概率较低，不采用。结果仍是 `rough`，不代表人工听音精校。对齐窗口、候选、选择理由和复现命令见 [末句证据](validation/tail-v4.1.json)。`tools/refine_timing.py --window START:END` 现在允许单组显式窗口，避免再被旧锚点裁断。

宿主保持从 191960 ms 开始；删除、完成、转黑分别为 205840、206820、207420 ms。保持期间没有新增宿主行或光标变化；字幕按音乐时间独立更新。
