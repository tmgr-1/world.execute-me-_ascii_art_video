# 实施与验收记录

记录日期：2026-10-17。基线：`design/design_doc_v2.md`。当前交付为可排演实现，正式发布验收尚未完成：209 个时间锚点仍是机器估计，未标记为人工精校。

## 实现与检查

- 影片包含 25 场、93 个歌词节点、cn/en 字典、六语言计数与独立字模；音乐仅由 `--music-file` 传入。
- 已实现 schema / 同源字节内存、请求事务、有限任务解释器、检查点重放、单次断开、自主任务、片段清零、根清除守卫、三秒冻结前景与只读补丁尾声。
- `npm run check`、`npm test`、`npm run test:e2e`、`npm run build` 通过。自动测试 31 项；伪终端覆盖正常退出、播放器异常、短段循环三种情况。
- 发布检查按预期拒绝当前 209 个 `rough` 锚点。不能用通过结构检查代替听音校准。
- FFmpeg 完整解码原 MP3 成功；mpv 使用空音频输出解码检查成功。未创建歌曲副本，原 MP3、参考歌词和设计文档未改写。
- 用户在普通终端已确认有歌曲和字符输出，随后反馈“基本准了”；完整观看和设备声画误差测量仍待完成。

发现并修复了一个实机问题：内部输出流改变行列后，没有向 terminal-kit 通知尺寸变化，导致目的区域仍裁切到初始 160×45。现在每次尺寸变化都会更新目的边界；回归测试检查 220×60、130×35、240×64 下实际输出的内存、变量和右下角内容。伪终端也覆盖 220×60 → 240×64；就绪页显示实际检测到的画布尺寸。

## 参考环境与性能

Ubuntu 26.04.1 LTS / x86_64；Intel Core i5-14600K；Node.js 24.19.0；mpv 0.41.0；FFmpeg 8.0.1；terminal-kit 3.1.4。基准使用项目 npm 脚本中的 Node 内存参数。

| 画布／语言 | 全曲采样数 | 平均帧耗时 | P95 | 峰值 RSS |
|---|---:|---:|---:|---:|
| 160×45 / cn，步长 33 ms | 6,423 | 1.023 ms | 1.734 ms | 129.37 MiB |
| 130×35 / en，步长 42 ms | 5,047 | 0.833 ms | 1.650 ms | 126.98 MiB |

上述数据在本轮时间轴细调前采集，仅含确定性模型推进和帧合成，不含终端编码、播放器、显示器或声音输出。原始数据见 [中文基准](validation/performance-cn.json) 与 [英文基准](validation/performance-en.json)。不能据此宣称整曲实机 RSS、声画误差或漂移已达标。

伪终端使用 `xterm-256color` 与明确的 JSON 播放器协议替身，检查备用屏幕、原始输入恢复、暂停／定位、缩小暂停、恢复不自动续播、背压和播放器异常。它不播放音乐，不证明音频设备延迟。自动化沙箱禁止 mpv 的本地 socket 发送系统调用（EPERM）；真实播放依赖用户普通终端复测。

PNG 帧检查采用 DejaVu Sans Mono 16 px / Noto Sans CJK 18 px，10×20 px 字符格；这不是设计中 1920×1080、15 号字体桌面环境的实测。用户的终端软件、字体、缩放、音频设备、开头／中段／高潮／尾声的声画延迟尚未记录。Windows、macOS 未测试。

## 时间轴精校

音轨时长 211.944 秒。原参考歌词 92 行，设计为 93 行；差异为重复的 `You have left`。按设计保留 93 节点，原文件保持原样。`timing-evidence.json` 保存分段强制对齐证据，不代表已听音复核。

本轮采用本地 small 权重，对 12 个短段重新对齐并以 20 ms 搜索步长细化边界，再与原分段对齐和独立转写比对。合并 32 处局部修正，其余未取得一致证据的位置保留原值。原始短段结果见 `films/world-execute/timing-refinement.json`；采用／推迟记录见 [时间轴比对](validation/timing-refinement.json)。没有修改全局偏移、剧情程序或将状态批量改为已精校。

较明显的修正为第 9 / 11 / 13 行原先被压为零时长的首词 If，分别提前 190 / 200 / 400 ms；第 85 行 I've studied 起点从 177580 调至 177360 ms。大部分其他修正在 10–40 ms 内。概率细化产生的过短词尾、重复 Execution 的大幅漂移及最后单词的裁切边缘命中均未直接采用。20 ms 搜索步长不代表 20 ms 实测精度。

当前估计：第 76 行结束 162300 ms；意图至 162550 ms；冻结至 165550 ms；补丁尾声从 177360 ms 开始。六个计数为 159190、159430、159880、160390、160790、161190 ms。第 76 行词尾的新候选为 162240 ms，因置信度不足而保留旧值。所有这些值均待听音复核。

可使用 `--rehearsal --loop 02:38..02:46` 反复试听计数和阻断，循环会精确定位媒体并重建模拟状态，不重复累积请求。仅在明确完成听音复核后，使用 `calibrate` 保存批准结果，并运行 `check --release`。
